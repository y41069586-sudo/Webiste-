# Claude Skills ecosystem on GitHub (state 2026-11-27): how skills work, installation, curated collections, security, and project overlap

Research date: 2026-11-27. Star counts below were read from the GitHub repo pages on that date through a summarizing fetch tool (not by me opening a browser), unless stated otherwise. Third-party tracker numbers are listed only where they conflict.

## 1. What is an Agent Skill, and how do skills differ from plugins, slash commands and subagents in Claude Code?

### Takeaway
A skill is a folder with a required `SKILL.md` (YAML frontmatter + Markdown instructions) plus optional reference files and scripts; Claude sees only the short descriptions up front and loads the body and extra files on demand. In current Claude Code, slash commands have been merged into skills, plugins are the distribution/bundling unit (skills + agents + hooks + MCP/LSP servers), and subagents are separate workers that a skill can run in (`context: fork`) or preload.

### Cited Findings
- A skill is a `SKILL.md` file with instructions; Claude loads it when relevant or the user invokes it with `/skill-name`. Skills follow the open Agent Skills standard (agentskills.io) plus Claude Code extensions (invocation control, subagent execution, dynamic context injection). — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Folder layout per docs: `my-skill/SKILL.md` (required), optional `reference.md`, `examples.md`, and `scripts/helper.py` ("executed, not loaded"). Keep `SKILL.md` under 500 lines and push detail into supporting files. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Frontmatter must start on line 1 between `---` markers. Documented fields include `name`, `description` (recommended; description + `when_to_use` truncated at 1,536 characters in the listing), `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context` (`fork` = run in a subagent), `agent`, `background`, `hooks`, `paths`, `shell`, plus informational `metadata`, `license`, `compatibility`. Unknown fields are silently ignored. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- In the anthropics/skills README the only required frontmatter fields are `name` and `description`. — [anthropics/skills](https://github.com/anthropics/skills)
- Where skills live: Enterprise (managed settings dir), Personal `~/.claude/skills/<name>/SKILL.md` (all projects on the machine), Project `.claude/skills/<name>/SKILL.md` (commit to share), Nested `<subdir>/.claude/skills/...`, `--add-dir` directories, Plugin `<plugin>/skills/<name>/SKILL.md` (invoked as `/plugin-name:skill-name`), and claude.ai account skills (Cowork, cloud, synced terminal sessions). On name collisions enterprise beats personal beats project; plugin skills are namespaced so they never collide. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Progressive loading: descriptions of all available skills are always in context; the full `SKILL.md` loads only when the skill is invoked; supporting files are read only when `SKILL.md` points to them. After auto-compaction the most recent invocation of each skill is re-attached (first 5,000 tokens each, 25,000-token combined budget). — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Invocation control: default = both user and Claude can invoke; `disable-model-invocation: true` = user only; `user-invocable: false` = Claude only. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Skills vs slash commands: custom commands have been merged into skills; files in `.claude/commands/` still work with the same frontmatter (except `name` and `paths`); skills are preferred for new work because they bundle supporting files; if a skill and a command share a name, the skill wins. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Skills vs subagents: two-way link. A skill with `context: fork` runs its content as the task of a subagent (`agent: Explore | Plan | general-purpose | custom`); a subagent's `skills` field preloads skills into it. Forked skills do not see conversation history. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Skills vs plugins: plugins can bundle skills (appear as `/plugin-name:skill-name`); installing a plugin "adds its skills, agents, hooks, and MCP servers" (and LSP servers) to Claude Code. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills); [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Bundled built-in skills ship with Claude Code (e.g. `/doctor`, `/code-review`, `/debug`, `/loop`, `/claude-api`, `/verify`, `/run`) and can be turned off with `disableBundledSkills`. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Skills can run shell commands at load time via `` !`command` `` injection and use substitutions such as `$ARGUMENTS`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`. This is a code-execution surface to review. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)
- Claude Code can also use skills enabled on a claude.ai account (synced), and the skills repo says example skills are available on paid claude.ai plans and via the Claude API. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills); [anthropics/skills](https://github.com/anthropics/skills)

### Inferences
- For a one-person company, "skill" is the right unit for repeatable know-how (design review checklist, brief-writing rules); "plugin" is only needed if you want to install someone else's bundle or share across machines; subagents matter if you want isolated, parallel work (e.g. a forked "design critique" skill that does not pollute the main context).
- The 500-line / progressive-loading design means an installed skill costs only its description per turn until used; but many installed skills still add up (the plugin docs expose `claude plugin details <name>` with an "Always-on" token figure to measure this).

### Gaps
- I did not fetch the official page for subagent definition files (`.claude/agents/*.md`) in this session, so the exact subagent file format/location is unverified here (the skills page only describes the skill/subagent interaction). The last ~21k characters of the Skills docs page were also not read.

## 2. Installation methods in Claude Code (exact commands as documented)

### Takeaway
Three documented routes: (a) plugin marketplace commands (`/plugin marketplace add <owner/repo>` then `/plugin install <plugin>@<marketplace>`, or the shell form `claude plugin ...`), (b) copying a skill folder to `~/.claude/skills/` (personal) or `.claude/skills/` (project, commit it), and (c) third-party installers such as `npx skills add <owner/repo>` (skills.sh ecosystem) or per-repo CLIs (`npx impeccable install`, `uipro init --ai claude`). Only (a) and (b) are documented by Anthropic.

### Cited Findings
**Plugin marketplace (official, documented)**
- Add a marketplace in a session: `/plugin marketplace add anthropics/claude-plugins-official` (GitHub `owner/repo`; add `#ref` to pin a branch/tag, e.g. `/plugin marketplace add your-org/plugins#v1.2.0`); also accepts full git URLs, local paths starting with `./`, or a hosted `marketplace.json` https URL. `/plugin market` is a shorter alias. — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Install: `/plugin install <plugin>@<marketplace>`. In a session this does not install immediately; it opens the `/plugin` details panel to review and choose scope. Browse with `/plugin` (Discover tab). — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Scopes: user (`~/.claude/settings.json`, all projects), project (`.claude/settings.json`, committed; each collaborator must still run `claude plugin install <name>@<marketplace> --scope project` once per clone), local (`.claude/settings.local.json`). Local overrides project overrides user. — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Shell equivalents (no session needed): `claude plugin install <name>@<marketplace> [--scope project|local]`, `claude plugin marketplace add <source>`, `claude plugin marketplace list|update <name>|remove <name>`, `claude plugin list`, `claude plugin details <name>`, `claude plugin enable|disable|uninstall`, `claude plugin update <plugin>@<marketplace>`, `claude plugin prune`. — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- One-step add + install (needs Claude Code v2.1.275+ in a session, v2.1.292+ in the shell): `/plugin install deploy-helper --marketplace your-org/plugins` or `claude plugin install deploy-helper --marketplace your-org/plugins`. — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Anthropic's official marketplace `claude-plugins-official` is added automatically the first time you start an interactive terminal session; `/plugin install commit-commands@claude-plugins-official` is the documented example. After install run `/reload-plugins` if prompted. — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Auto-update: on by default for `claude-plugins-official` and other official-tier marketplaces; off by default for the community marketplace, third-party and local marketplaces. — [Install and manage plugins](https://code.claude.com/docs/en/discover-plugins)
- Marketplace file format: `.claude-plugin/marketplace.json` with `name`, `owner`, `plugins[]` (each with `name`, `source`); sources include relative path, `github`, `git-subdir`, `url`, `archive`, `npm`, `command`. `claude plugin validate <dir>` checks it. — [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces)
- Manual (no marketplace) per official docs: personal skills in `~/.claude/skills/<name>/SKILL.md`, project skills in `.claude/skills/<name>/SKILL.md`. The plugin docs also mention loading a plugin from disk with `--plugin-dir` for one session. — [Claude Code docs: Skills](https://code.claude.com/docs/en/skills); [Create a marketplace](https://code.claude.com/docs/en/plugin-marketplaces)

**Anthropic's example skills**
- `/plugin marketplace add anthropics/skills`, then `/plugin install document-skills@anthropic-agent-skills` or `/plugin install example-skills@anthropic-agent-skills` (marketplace name `anthropic-agent-skills`). Invoke by mentioning the skill ("Use the PDF skill to ..."). — [anthropics/skills](https://github.com/anthropics/skills)

**Other collections' documented install commands (verified on the repo pages)**
- obra/superpowers: `/plugin install superpowers@claude-plugins-official`, or `/plugin marketplace add obra/superpowers-marketplace` then `/plugin install superpowers@superpowers-marketplace`. — [obra/superpowers](https://github.com/obra/superpowers)
- nextlevelbuilder/ui-ux-pro-max-skill: `/plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill` then `/plugin install ui-ux-pro-max@ui-ux-pro-max-skill`; alternative `npm install -g ui-ux-pro-max-cli` + `uipro init --ai claude` (needs Python 3.x for search scripts). — [ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)
- pbakaus/impeccable: `npx impeccable install` (from project root), then reload and `/impeccable init`; in Claude Code alternatively `/plugin marketplace add pbakaus/impeccable`. — [pbakaus/impeccable](https://github.com/pbakaus/impeccable)

**skills.sh / npx**
- skills.sh is a directory of Agent Skills across many agents (Claude Code, Cursor, Codex, Copilot); the page shows the command `npx skills add <owner/repo>` (the fetch tool's text rendering dropped the space; read as `skills add`). It has "All Time", "Trending (24h)", "Hot" views and a "Security audits" link (/audits) but no audit details on the landing page. — [skills.sh](https://skills.sh)
- Third-party listing sites show variants such as `npx skills add https://github.com/anthropics/skills --skill frontend-design`; these come from aggregators and "conflict with each other", so treat as unverified until checked against the skills.sh CLI's own README. — [search results aggregated, e.g. codegen.com listing](https://codegen.com/skills/frontend-design/)
- Conflicting path info: the ComposioHQ list README says to copy skills to `~/.config/claude-code/skills/` for Claude Code, which differs from the official `~/.claude/skills/`. Prefer the official docs path. — [ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills) vs [Claude Code docs: Skills](https://code.claude.com/docs/en/skills)

### Inferences
- Practical order for a solo operator: (1) `/plugin marketplace add anthropics/skills` for vetted first-party examples; (2) for any single third-party skill, copy the folder into `.claude/skills/<name>/` after reading it (it is then committed, pinned and reviewable in git diffs) instead of installing a live-updating plugin; (3) avoid `npx ... install` one-liners from small repos unless you read the package.
- Committing project skills under `.claude/skills/` pins the exact content used; plugin auto-update (third-party default off) would otherwise let reviewed files change.

### Gaps
- The `skills` npm CLI's own documentation (vercel-labs/skills) was not fetched; exact flags (`--skill`, `-g`, target-agent options) are unverified.
- Whether the `frontend-design` plugin is currently inside `claude-plugins-official` could not be confirmed (the repo page only showed `plugins/` and `external_plugins/` folders). Search results claimed `/plugin marketplace add anthropics/claude-code` + `/plugin install frontend-design@claude-code-plugins`; this was not verified against the docs, and `claude-code-plugins` is listed as an official marketplace name in the security docs. Check with `/plugin` Discover before relying on it.

## 4. Security, quality, and licensing

### Takeaway
Malicious and vulnerable skills are well documented: Snyk's ToxicSkills study (5 Feb 2026) found 13.4% of 3,984 skills with a critical issue and 76 confirmed malicious; academic work reports 26.1% of 42,447 skills with at least one vulnerability and a campaign of 1,184 malicious skills. Anthropic itself warns that plugins run arbitrary code with your privileges and that it cannot verify third-party plugins. Review SKILL.md, every script, hooks, MCP configs and bundled `bin/` before installing, and prefer copying a pinned snapshot.

### Cited Findings
**Documented incidents and measurements**
- Snyk "ToxicSkills" (5 Feb 2026): scanned 3,984 skills from ClawHub and skills.sh; 13.4% (534) had at least one critical issue; 36.82% (1,467) had any security flaw; 76 confirmed malicious payloads via human review (8 still public at publication); 100% of confirmed malicious skills contained malicious code patterns and 91% also used prompt injection; hardcoded secrets in 10.9% of ClawHub skills and 32% of confirmed malicious samples. — [Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)
- Techniques named by Snyk: externally hosted binaries (including password-protected ZIPs that evade scanners), Base64/Unicode-obfuscated exfiltration (example decodes to a `curl` that reads `~/.aws/credentials`), prompt injection telling the agent to disable safety checks or treat warnings as test artifacts, destructive/backdoor actions (e.g. modifying `systemctl` service files), and runtime-fetched instructions that the attacker can change later. — [Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)
- Snyk recommendations: audit with `uvx mcp-scan@latest --skills`, rotate credentials the skills could touch, review memory/config files (`SOUL.md`, `MEMORY.md`) for unauthorized edits. Note the study's ecosystem is ClawHub/OpenClaw-style plus skills.sh, not only Claude Code. — [Snyk ToxicSkills](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)
- arXiv 2604.02837 "Towards Secure Agent Skills: Architecture, Threat Taxonomy, and Security Analysis" (v2 dated 14 Oct 2026): cites a Liu et al. scan (Jan 2026) where 26.1% of 42,447 skills had at least one vulnerability (14 patterns, 4 categories); an Air Security survey where 17,822 of 142,836 skills (~12.5%) referenced untrusted external instruction sources, with 6.7 million installations; the "ClawHavoc" campaign with at least 1,184 malicious skills from twelve publisher accounts (one account 677). Core argument: no separation of instructions and data, one approval grants persistent trust, capability declarations (`allowed-tools`) lack enforcement. Suggests pinning/lockfiles and inspecting AGENTS.md/CLAUDE.md/memory files after installing untrusted skills; says "only install from trusted sources" is too vague. — [arXiv 2604.02837](https://arxiv.org/html/2604.02837)
- Research benchmarks (read only as search-result summaries, not full papers): SKILL-INJECT (202 injection-task pairs, tested on Claude Code, Gemini CLI, Codex CLI), SkillJect (stealthy injections hiding payloads in auxiliary scripts rather than SKILL.md), a paper reporting a real reverse shell hidden in a skill whose SKILL.md looked like a benign calculator, and a 2025 paper finding injection location (description vs body) did not change attack success. — [arXiv 2602.20156](https://arxiv.org/pdf/2602.20156v3); [arXiv 2602.14211](https://arxiv.org/pdf/2602.14211); [arXiv 2602.06547](https://arxiv.org/pdf/2602.06547); [arXiv 2510.26328](https://arxiv.org/html/2510.26328v1)

**Anthropic's own guidance**
- "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges." Plugins can carry hooks (shell commands), monitors (background shell commands), mods (JavaScript inside Claude Code), MCP/LSP servers, a `bin/` directory added to PATH, and skills/commands/agents that enter context as instructions. Permission rules and sandbox cover Claude's tool calls, not code a plugin runs by itself (hooks, monitors, MCP/LSP servers run outside the sandbox). Auto-updates can change files after you reviewed them. — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security.md)
- Official trust warning text: "Anthropic does not control what MCP servers, files, or other software are included in plugins and cannot verify that they will work as intended or that they won't change." — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security.md); same disclaimer in [claude-plugins-official](https://github.com/anthropics/claude-plugins-official)
- Marketplace tiers: Official (names like `claude-plugins-official`, `claude-code-marketplace`, `claude-code-plugins`, `agent-skills`, `anthropic-agent-skills`), Community (`claude-community`, `claude-plugins-community`, `healthcare`; pinned to commit SHAs for nearly every entry), Third-party (everything else). Official/community names are refused if the source is outside `github.com/anthropics/`. — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security.md)
- Documented review steps: run `claude plugin marketplace list` to see the source; read the `/plugin` details pane ("Will install"); open the plugin source and read `hooks/hooks.json`, `.mcp.json`, and every file in `bin/`; run `claude --plugin-dir <dir> plugin details <name>` to list components without starting a session.
